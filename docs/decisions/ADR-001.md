# ADR-001: Rebuild as a Web-Only Application

## Status
Accepted

## Date
2026-07-29

## Context
The original MindBridge AI was built as an Android application using Expo and React Native. Stakeholders requested a professional, responsive, scalable web application that preserves all existing functionality while improving usability, maintainability, and reach across devices (desktop, tablet, and mobile).

Key drivers:
- Support for a broad user base without requiring app-store distribution or mobile installs.
- Consistent desktop-grade analytics, reporting, and export workflows.
- Easier deployments, continuous delivery, and accessibility compliance.
- Reduced platform-specific maintenance by targeting a single runtime (the browser).

## Decision
Rebuild the application as a web-only application using React with TypeScript and Vite for the frontend, and a Node.js/Express REST API for the backend. Remove the Expo-specific mobile codebase and replace it with responsive web pages.

## Alternatives Considered

### Keep React Native and add a web build (React Native Web)
- Pros: Reuses existing mobile screens, single codebase for mobile + web.
- Cons: Web UX is mobile-first and hard to adapt to desktop dashboards; export/reporting features are awkward on mobile components; continued native toolchain dependency.
- Rejected: Did not meet the goal of a professional desktop-grade web experience.

### Build a separate mobile app and web app
- Pros: Could optimize each platform independently.
- Cons: Duplicates business logic and maintenance; exceeds project scope and budget.
- Rejected: The mandate is to rebuild the existing app as a web app, not maintain both.

### Progressive Web App (PWA) wrapper
- Pros: Installable, offline-friendly, and can reuse web code.
- Cons: Still a mobile-first experience; not the best fit for heavy admin dashboards.
- Rejected: A standard responsive web app is sufficient for the target audience and avoids extra PWA complexity.

## Consequences
- All screens, navigation, auth flows, and business logic are recreated as web pages.
- Mobile-specific code is removed, simplifying the project structure.
- The codebase can be hosted as a single domain, served by any static-hosting-compatible CDN.
- Future native mobile support would require a separate decision, not incremental reuse of the current project.
