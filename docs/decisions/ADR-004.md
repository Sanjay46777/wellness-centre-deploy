# ADR-004: Authentication and Authorization — JWT with Role-Based Access

## Status
Accepted

## Date
2026-07-29

## Context
The application supports three primary roles: student, head_counsellor, and admin. Students can submit feedback; head counsellors can view institution analytics and counsellor details; admins can manage counsellors and approve pending head-counsellor registrations. The system must be secure, stateless, and easy to reason about.

## Decision
Implement JWT-based authentication:
- Passwords are hashed with bcrypt before storage.
- On login, the server issues a short-lived JWT containing the user's ID, email, and role.
- Protected routes validate the JWT and check the user's role against an allowed list.
- The frontend stores the token in memory (Zustand) and sends it in the `Authorization: Bearer <token>` header.
- The head-counsellor registration flow requires admin approval before the account becomes active.

## Alternatives Considered

### Session cookies with server-side sessions
- Pros: Easy revocation, built-in CSRF protection with same-site cookies.
- Cons: Requires sticky sessions or shared session storage; complicates horizontal scaling.
- Rejected: JWT is simpler for a stateless REST API and matches the requested stack.

### OAuth / SSO
- Pros: Users can authenticate with existing institutional accounts.
- Cons: Requires integration with IIT Madras identity provider; adds scope and external dependency.
- Rejected: Email/password with JWT is sufficient for the current phase and can be extended later.

### Token stored in localStorage
- Pros: Simple to implement on the client.
- Cons: Vulnerable to XSS theft.
- Rejected: The token is kept in application state, and XSS is mitigated by output encoding and CSP (via Helmet).

## Consequences
- The backend is stateless and horizontally scalable.
- Token expiration is handled by forcing re-login.
- Role-based route guards are enforced both on the frontend (UX) and backend (API).
- A compromised secret requires rotating `JWT_SECRET` and logging all users out.
